# ethos 网关协议（Rust 网关复刻规范）

> 定位：ethos 是**协议定义方**（纯 Python 库），Rust 网关是**协议复刻方**（独立进程，不 import share-core / ethos，按本协议实现等价逻辑）。
>
> 适用：zervi-rust 系网关（axum + tokio）或任何需要对接 Tatha / ai-service / share-core 消费方的高并发入口。
>
> 版本：v1（对齐 ethos 0.1.0 实现，代码即规范，以 `src/ethos/security/` 与 `src/ethos/resolver/` 为最终依据）。

---

## 0. 协议全景

| 段落 | 职责 | ethos 实现 | Rust 网关复刻 |
|---|---|---|---|
| §1 令牌 | 验证外部签发的 JWT（ethos 库不签发；签发职责见 §1.5） | `HmacJwtVerifier` | `jsonwebtoken` HS256 验签 |
| §1.5 签发职责 | 运行时系统自动签发 + 超管例外（ethos 库不签发） | `SystemMinter`（Tatha 接入层） | 网关不做签发，仅验签 |
| §2 鉴权 | 档位 / 权限判定 | `TierAuthorizer` / `PermissionAuthorizer` | 等价 tier 比较 + 权限表 |
| §3 配额 | 计数与超限判定 | `QuotaManager` + `Local/RemoteQuotaBackend` | 网关自持或转发配额中心 |
| §4 审计 | 本地落库 + 可选上报 + 旧表自动迁移 | `Auditor` + `Sqlite/Jsonl/Http` | 网关本地落库 + POST 上报中心 |
| §5 错误码 | 401 / 403 / 429 语义 | 各模块 error/reason 字段 | HTTP 状态码映射 |

**核心原则**：

1. **ethos 是纯验证者**——库内验签、鉴权、计数、审计，唯独不签发令牌。签发职责在应用层：运行时系统自动签发（§1.5），用户令牌由 Go 8207 / Rust auth-service / Supabase 签发。
2. **`sub` 是唯一 uid 桥梁**——所有消费方看到的 `user_id` 一律取 `sub`（兼容 `user_id`/`uid`）。
3. **deny by default**——验签失败、scope 未配置、配额后端不可达、验签通过但 uid 为空，一律拒绝，不允许静默放行。

## 1. 令牌协议

### 1.1 格式

标准 JWT：`header.payload.signature`，三段均 base64url（无 padding）。

```jsonc
// header（验签前强制校验）
{"alg": "HS256", "typ": "JWT"}

// payload（Claims，见 §1.2）
{"sub": "user-123", "tier": "pro", "role": "user", "exp": 1750000000, ...}
```

**alg 白名单：仅 `HS256`**。`alg=none`、`HS384`、`RS256` 一律拒绝（防混淆攻击）。

### 1.2 Claims 契约（宽容解析）

| 语义 | 优先键 | 兼容键 | 说明 |
|---|---|---|---|
| 用户 uid | `sub` | `user_id`, `uid` | **跨端唯一身份**；缺失时验证视为失败（`Principal.sub` 为空） |
| 档位 | `tier` | `plan`, `level` | 见 §2.1 别名表；档位键缺失时退化用 `roles[0]` |
| 角色 | `roles` | `role`（单值）, `authorities` | 字符串或字符串数组均可 |
| 权限 | `permissions` | `scope`, `scopes` | 字符串（空格/逗号分隔）或数组均可 |
| 租户 | `tenant_type` | `tenant` | 与多租户体系对齐 |
| 用户名 | `username` | `name` | 仅展示，不参与鉴权 |
| 过期时间 | `exp` | — | unix 秒；**缺省视为不过期**（宽容策略，对齐 tenet `validate_exp=False`） |
| 签发时间 | `iat` | — | unix 秒 |

**验签失败即整个验证失败**；Claims 键不匹配只是"解析为空"，不拒绝——这是与"同一 secret 下两套 Claims 共存"的现实对齐（Rust 用 `sub`，Go 用 `user_id`，两边 token 都能验通，`sub` 是交集）。

> **deny by default（消费方职责）**：ethos 验签对缺失 `uid` 是宽容的（解析出空 `user_id`，验签仍通过）。**消费方必须拒绝空 `user_id`**——业务（配额、审计、鉴权）需要真实身份，Tatha 接入层在 `authenticate` 已实现（`not principal.user_id → 拒绝`）。Rust 网关同样：验签通过但 uid 为空 → 401。

### 1.3 密钥注入与轮换

```
ETHOS_AUTH_SECRET      # 主密钥（必填）
EXTRA_AUTH_SECRETS     # 逗号分隔的轮换期旧密钥（可选）
```

- 验签顺序：主密钥 → 附加密钥，任一通过即成功。
- 网关侧环境变量名可自定义，但必须与 ethos 消费方注入**同一组值**。
- **禁止默认值**：生产环境未配置 `ETHOS_AUTH_SECRET` 时必须拒绝启动或进入 Stub 模式（Stub 仅限本地联调，绝不允许出现在公网入口）。

### 1.4 验证结果结构

```jsonc
// 成功
{"verified": true, "principal": {"sub": "user-123", "tier": "pro", "roles": ["user"], "permissions": [], "tenant_type": null}}

// 失败（error 三选一）
{"verified": false, "error": "missing token"}
{"verified": false, "error": "invalid signature or malformed token"}
{"verified": false, "error": "token expired"}
```

### 1.5 签发职责（运行时自动 + 超管例外）

**ethos 库保持纯验证者，不签发**；签发职责落在"运行时系统"与"受控运维入口"（Tatha `SystemMinter`）：

1. **运行时系统自动签发（无人干预）**：服务启动 `bootstrap()` 自动签发系统令牌
   （`sub=svc:tatha`，`tier=admin`，`roles=["system"]`，含 `iat/exp`），过期惰性续签；
   每次签发落审计 `system.token.issued`（可溯源）。整个生命周期无人工介入。
2. **不被人为左右**：登录/注册等业务接口**不签发**（Tatha `login/register` 恒回落 demo-token /
   外部签发方）；普通请求不可能触发签发。
3. **超级管理员例外**：`POST /v1/admin/tokens` 持超管/系统令牌者（`tier=admin` 或
   `roles` 含 `admin/super_admin/system`）可按需签发任意主体令牌，签发落审计 `admin.mint`。

> **签发必须用同一组 secret**（`ETHOS_AUTH_SECRET`），保证 ethos 消费方与 Rust 网关都能验通。
> 系统令牌等同超管权限，仅限内部服务间调用，**严禁暴露给公网**。

## 2. 鉴权协议

### 2.1 档位（tier）语义

四档有序：`free < basic < pro < admin`。

| ethos 值 | 别名（Claims 中出现的写法） |
|---|---|
| `free` | free（默认） |
| `basic` | basic, bronze, starter, standard |
| `pro` | pro, premium, gold, vip, silver |
| `admin` | admin, super_admin, root |

**admin 是越权档**：任何 scope 直接放行（`admin bypass`），不参与档位比较。

### 2.2 判定规则

- **档位模式**（默认）：`scope → 最低档位` 策略表，未列出的 scope **默认拒绝**（特殊键 `"*"` 可设全局兜底）。
- **权限模式**：`scope → 所需 permission` 策略表；principal 拥有 `"*"` 或为 admin 时放行。
- 未认证（无 principal）一律拒绝，reason=`unauthenticated`。

```jsonc
// 策略表示例（Tatha 用）
{
  "ask":        "free",
  "rag.query":  "pro",
  "jobs.match": "free",
  "*":          null            // 未列出 scope 的兜底，null = 拒绝
}

// 判定结果
{"allow": true,  "reason": "pro >= pro"}
{"allow": false, "reason": "need tier pro, got free"}
{"allow": false, "reason": "scope 'admin.x' 未在策略中，默认拒绝"}
```

## 3. 配额协议

### 3.1 计数键

```
{tenant}:{user_id}:{resource}
tenant 缺省为 "default"（与 Go 多租户字段对齐，避免跨服务撞名）
```

示例：`default:user-123:ai:resume_analysis`。

### 3.2 语义

| 操作 | 行为 |
|---|---|
| `check` | 查询剩余，**不计数** |
| `consume` | 计数并返回最新状态；超限返回 `ok=false` 且**不改变计数** |
| 重置 | 默认自然日归零；`LocalQuotaBackend` 支持自定义窗口秒数 |

- `daily=0` 表示该资源不限制（返回 `remaining=-1, ok=true`）。
- 资源未配置配额：视为不限制（返回 `remaining=-1, ok=true`）。

### 3.3 返回结构

```jsonc
{"resource": "ai:resume_analysis", "remaining": 3, "limit": 5, "ok": true, "message": ""}
{"resource": "ai:resume_analysis", "remaining": 0, "limit": 5, "ok": false, "message": "daily quota exhausted"}
```

### 3.4 远程 HTTP 协议（网关复刻时选其一）

**方案 A：网关自持配额中心**——实现下面这个端点，ethos 消费方通过 `RemoteQuotaBackend` 对接：

```
POST {base_url}/quota
Content-Type: application/json

{"key": "default:user-123:ai:resume_analysis", "resource": "ai:resume_analysis", "amount": 1, "tenant": "default"}

200 → {"ok": true, "remaining": 3, "limit": 5, "message": ""}
404 → 端点不存在（ethos 抛错，由调用方决定降级本地还是拒绝）
```

**方案 B：网关只做转发**——网关内部调统一认证服务的配额端点，语义同上，超限在网关注入 429。

> 注意：`RemoteQuotaBackend` 发的是 **amount 语义**（每次调用消耗量），不是"查了再说"。消费方应只对**实际执行的调用** `consume`，对**预检**用 `check`。

## 4. 审计协议

### 4.1 事件结构（`AuditEvent`）

```
action    : str    动作名（如 "ask"、"rag.query"、"documents.convert"）
principal : 主体    （取 user_id / tier）
resource  : str    资源标识（默认 ""）
meta      : dict   扩展字段（业务上下文，序列化时展开到顶层）
ts        : float  unix 秒
```

**上报 payload**（`to_dict()`，meta 展开到顶层）：

```jsonc
{"ts": 1750000000.12, "action": "ask", "resource": "", "user_id": "user-123", "tier": "pro", "intent": "match_jobs", "status": "ok", "latency_ms": 823, "quota_after": 4, "request_id": "req-9f1a"}
```

### 4.2 本地落库表（网关自持时按此结构建表）

```sql
CREATE TABLE IF NOT EXISTS audit_log (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    ts       REAL    NOT NULL,
    action   TEXT    NOT NULL,
    user_id  TEXT    DEFAULT '',
    tier     TEXT    DEFAULT '',
    resource TEXT    DEFAULT '',
    meta     TEXT    DEFAULT '{}'
);
CREATE INDEX IF NOT EXISTS idx_audit_user   ON audit_log (user_id, ts);
CREATE INDEX IF NOT EXISTS idx_audit_action ON audit_log (action, ts);
```

### 4.3 上报中心

`HttpReporter`：异步（独立线程）`POST event.to_dict()` 到上报中心，**best-effort**——失败仅告警，绝不阻塞业务主流程。

### 4.4 旧表迁移（升级统一）

ethos `SqliteAuditor` 打开已有库时**自动检测并迁移 tenet 旧版 `audit_log`**（特征：含 `request_id`
列、`ts` 为 TEXT），全服务切换即整齐划一，无需手动删库：

- 旧表整体改名 `audit_log_legacy`（**原始数据保留，可溯源**）；
- 按 §4.2 结构重建 `audit_log`，旧行逐条迁入：
  `ts` 文本转 unix 秒（REAL）；`request_id/intent/status/latency_ms/quota_after/detail` 并入 `meta` JSON；
- 幂等：ethos 新表无 `request_id` 列，不会重复迁移；迁移后新事件正常落库。

> 升级路径：Tatha 首次切换 ethos 时，旧 `logs/audit.db` 无需手动删除——启动时自动迁移。

## 5. 错误码约定

| HTTP | 触发 | 响应体（消费方约定） |
|---|---|---|
| 401 | 验签失败 / 缺 token | `{"detail": "..."}` |
| 403 | 鉴权拒绝 | `{"code": "forbidden", "message": "<decision.reason>"}` |
| 429 | 配额超限 | `{"code": "quota_exceeded", "message": "当日配额已用尽，请升级后继续使用。"}` |

## 6. Rust 网关复刻 Checklist

- [ ] **JWT 验签**：`jsonwebtoken`，`Validation::new(Algorithm::HS256)`，主密钥 + 轮换旧密钥数组；`alg` 白名单仅 HS256。
- [ ] **Claims 宽容解析**：uid 依次尝试 `sub → user_id → uid`；角色 `roles → role → authorities`；档位 `tier → plan → level → roles[0]`；权限 `permissions → scope → scopes`。
- [ ] **uid 空值拒绝**：验签通过但 uid 为空 → 401（与消费方语义一致，见 §1.2）。
- [ ] **exp 宽容**：缺省不校验（与 ethos 一致）；存在则 `exp < now` 判过期。
- [ ] **签发职责**（网关若兼签发方）：仅运行时系统自动签发（svc 令牌 + `system.token.issued` 审计）与超管 mint（`admin.mint` 审计），业务接口不签发；系统令牌严禁暴露公网（§1.5）。
- [ ] **档位别名表**：free/basic/pro/admin + 别名（§2.1），admin 直接 bypass。
- [ ] **鉴权策略表**：scope → tier（未列出拒绝）；未认证一律拒绝。
- [ ] **配额**：方案 A 或 B（§3.4）；计数键 `{tenant}:{user_id}:{resource}`，`daily=0` 不限制，超限返回 429。
- [ ] **审计**：本地落库（§4.2 表结构）+ 可选异步上报中心（§4.3 payload）。
- [ ] **审计旧表迁移**：检测 `request_id` 列（tenet 旧表）→ 改名 `audit_log_legacy` + 重建 §4.2 结构 + 数据迁入 meta（§4.4）。
- [ ] **错误码映射**：401/403/429 按 §5。
- [ ] **密钥管理**：禁止默认 secret；生产未配置拒绝启动或退 Stub（Stub 仅限本地）。

## 7. 消费方对接（Python 侧等价用法）

```python
from ethos.models import QuotaLimit
from ethos.security import init_security

sec = init_security(
    secret=os.getenv("ETHOS_AUTH_SECRET"),           # 主密钥
    tier_policy={"ask": "free", "rag.query": "pro"}, # 档位策略
    quota_limits={                                    # 配额上限（QuotaLimit 对象）
        "ai:resume_analysis": QuotaLimit("ai:resume_analysis", daily=5),
    },
    audit_db="logs/audit.db",                        # 本地审计
)

ctx = sec.verify(token)                             # 验签
sec.authorize(ctx, "rag.query")                     # 鉴权 → Decision
sec.consume_quota(ctx, "ai:resume_analysis")        # 配额（ctx.principal 非空才计数）
sec.audit("ask", principal=ctx.principal, meta={...})  # 审计
```
