# szpeter2026 快速开始指南

## 第一步：环境检查

```powershell
# 确认 Python 版本（需要 3.10+）
python --version
```

## 第二步：初始化

```powershell
cd E:\szpeter2026
.\scripts\manage.ps1 -Action setup
```

这会：
- 安装 Python 依赖
- 创建 `.env` 配置文件
- 初始化 SQLite 元数据库（含断点续传表结构）

## 第三步：配置 AI

编辑 `.env` 文件：

**使用 DeepSeek（推荐，开箱即用）：**
```env
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-your-deepseek-api-key
```

**使用 Ollama（本地，免费，隐私）：**
```env
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2:latest
```

## 第四步：启动 Web 面板

```powershell
.\scripts\manage.ps1 -Action web
# 访问 http://127.0.0.1:5220
```

> **ChromaDB 默认本地模式**：向量数据自动存储于 `db/d_index_data/`，无需 Docker。如需 Docker Chroma 服务，见下方「可选：Docker 部署」。

## 第五步：D 盘代码索引（D-Indexer）

### 首次全量扫描

启动 Web 面板后，D-Indexer 调度器在后台自动运行。通过 API 触发首次扫描：

```powershell
# 断点续传式全量扫描（推荐，支持中断恢复）
curl -X POST http://127.0.0.1:5220/api/d-index/scan ^
  -H "Content-Type: application/json" ^
  -d "{\"mode\": \"resume\"}"
```

### 查看扫描进度

```bash
# 查看所有项目的断点/进度
curl http://127.0.0.1:5220/api/d-index/checkpoint
```

响应示例：
```json
{
  "projects": [
    {
      "project_root": "D:/jobfirst-claw",
      "status": "in_progress",
      "completed_dirs_count": 45,
      "files_scanned": 320,
      "files_indexed": 280
    }
  ],
  "has_incomplete": true,
  "cache": {"total_cached_files": 1520}
}
```

### 代码语义搜索

```bash
curl -X POST http://127.0.0.1:5220/api/d-index/search ^
  -H "Content-Type: application/json" ^
  -d "{\"query\": \"用户认证逻辑\", \"top_k\": 5}"
```

### 增量扫描（日常使用）

```bash
# 仅索引变更文件（文件缓存 10-100x 加速）
curl -X POST http://127.0.0.1:5220/api/d-index/scan ^
  -H "Content-Type: application/json" ^
  -d "{\"mode\": \"incremental\"}"
```

### 扫描模式对比

| 模式 | API mode 值 | 说明 |
|------|-------------|------|
| 断点续传 | `resume` | 从中断处继续，跳过已完成目录（推荐首次使用） |
| 增量 | `incremental` | 仅索引变更文件，文件缓存加速（日常使用） |
| 全量 | `full` | 重置所有断点，从头扫描（慎用，耗时数小时） |

## 第六步：导入文档

将你的文档放到 `knowledge_base/documents/` 目录下，然后：

```powershell
.\scripts\manage.ps1 -Action import
```

支持格式：`.md` / `.pdf` / `.txt` / `.docx`

## 可选：Docker 部署

如需 Chroma 向量服务 + pgvector + Ollama Embedding 全套 Docker 环境：

```powershell
cd "D:\Program Files\Docker"
docker compose up -d
```

这会启动 4 个容器：
- `szpeter2026-postgres` — PostgreSQL 17 + pgvector (:5432)
- `szpeter2026-chroma` — Chroma 向量库 (:8000)
- `szpeter2026-ollama` — Ollama LLM + Embedding (:11434)
- `szpeter2026-ollama-init` — 自动拉取模型（运行完退出）

编辑 `.env` 切换到 Docker 模式：
```env
CHROMA_MODE=remote
CHROMA_HOST=localhost
CHROMA_PORT=8000
PGVECTOR_ENABLED=true
```

三种 Chroma 模式：

| 模式 | 配置 | 说明 |
|------|------|------|
| `persistent` | 默认 | 纯本地文件存储，零依赖（D-Indexer 推荐） |
| `remote` | `CHROMA_MODE=remote` | 使用 Docker Chroma 服务 |
| `auto` | `CHROMA_MODE=auto` | 自动检测 Docker 服务，不可用时回退本地 |

## 故障排查

### ChromaDB 不可用

D-Indexer 默认使用本地 PersistentClient 模式（`db/d_index_data/`），不依赖 Docker。如遇 Chroma 错误：

```powershell
# 检查 persist 目录
dir db\d_index_data\
```

### 扫描中断后恢复

```bash
# 查看中断状态
curl http://127.0.0.1:5220/api/d-index/checkpoint
# 从中断处继续
curl -X POST http://127.0.0.1:5220/api/d-index/scan ^
  -H "Content-Type: application/json" ^
  -d "{\"mode\": \"resume\"}"
```

### Docker Chroma 不可用

系统自动回退到本地持久化模式（auto 默认行为），不影响使用。

手动检查：
```powershell
docker ps | findstr chroma
# 如果没有运行：
cd "D:\Program Files\Docker\chroma"
docker compose up -d
```

### DeepSeek API 报错

检查 `.env` 中的 `DEEPSEEK_API_KEY` 是否正确。

### 端口被占用

修改 `.env` 中的 `WEB_PORT`：
```env
WEB_PORT=5201
```
