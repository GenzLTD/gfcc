# szpeter2026 架构设计

## 设计理念

吸收自 Wukong 工作区三大项目的精华：

1. **Wukong** — 多源元数据管理、schema 映射、工具链设计
2. **72changes** — RAG 知识库、Chroma + AI 问答
3. **data/** — 多数据库统一运维、Web 看板

## 核心设计决策

### 1. 为什么选择 Python + Flask + SQLite？

- **轻量零配置**：无需 Java/Maven/Docker 等重型依赖
- **快速启动**：单文件 SQLite 元数据库，无需安装数据库服务
- **统一技术栈**：Python 贯穿文档处理、向量检索、AI 调用、Web 面板
- **易于扩展**：Flask 插件生态丰富，可方便扩展 API

### 2. 为什么选择 ChromaDB PersistentClient？

- **零依赖本地运行**：向量数据直接存文件系统（`db/d_index_data/`），无需 Docker
- **自动嵌入**：内置 `all-MiniLM-L6-v2` 默认嵌入函数，开箱即用
- **可选 Docker 升级**：需要远程访问或生产部署时切换到 HttpClient 模式
- **备选 pgvector**：基于 PostgreSQL，支持向量+关系数据混合查询

### 3. AI 双模式设计

```
AIClient
├── DeepSeek 模式（默认）
│   └── 云 API，质量高，需联网和 API Key
└── Ollama 模式（备选）
    └── 本地运行，隐私好，需 GPU/内存
```

两个模式接口完全一致，切换只需改 `.env` 中 `AI_PROVIDER`。

### 4. 文档处理管道

```
扫描目录 → 过滤格式(md/pdf/txt)
    → PDF: pdfplumber → pypdf 回退
    → MD/TXT: 直接读取
→ 按 Markdown 标题 + 自然段落分块
→ 带重叠的分块（overlap=200）
→ 写入 SQLite + Chroma
```

### 5. RAG 流程

```
用户问题
    ↓
混合检索（Chroma 语义 + FTS5 全文 → RRF 融合）
    ↓
构建增强上下文（来源标注）
    ↓
AI 生成（DeepSeek/Ollama）
    ↓
返回：回答 + 来源 + 耗时 + 参考块数
```

## D-Indexer：D 盘代码索引架构

### 设计目标

自动扫描 D 盘 22 个项目目录，将源代码/配置文件向量化存入 ChromaDB，支持"那个做跨境电商的项目在哪"式语义搜索。

### 模块分层

```
d_indexer/
├── scanner.py      # 文件扫描器（os.walk + 30+ 扩展名过滤）
├── checkpoint.py   # SQLite 断点管理器（持久化扫描状态 + 文件缓存）
├── indexer.py      # Chroma 向量索引器（支持断点续传）
├── scheduler.py    # 每日定时扫描调度器
└── projects.py     # D 盘项目根目录配置（22 个）
```

### 断点续传机制

```
┌──────────┐    ┌───────────────┐    ┌──────────┐
│ Scanner   │ →  │ Checkpoint    │ →  │ ChromaDB │
│ 续传模式  │    │ Manager       │    │ upsert    │
└──────────┘    └───────┬───────┘    └──────────┘
                        │
              ┌─────────▼──────────┐
              │  SQLite (WAL)      │
              │  scan_checkpoints  │  ← 目录级断点
              │  indexed_files_cache│ ← 文件级缓存
              └────────────────────┘
```

**目录级断点**：每处理完一个目录立即持久化到 `scan_checkpoints.completed_dirs`。崩溃重启后，`os.walk` 通过 `dirnames.remove()` 直接跳过已完成目录（零开销）。最多丢失一个目录内的进度。

**文件级缓存**：`indexed_files_cache` 表存 `(path, size, mtime, fingerprint)`。增量扫描时三者全匹配 → 不读文件、不查 ChromaDB、直接跳过（10-100x 加速）。

**自动续传**：调度器启动时检测 `status='in_progress'` 的记录，立即从中断处继续。

## 与 Wukong 的对比

| 维度 | Wukong | szpeter2026 |
|------|--------|-------------|
| 定位 | 跨境数据共识匹配平台 | 个人知识 + 代码索引管理平台 |
| 规模 | 103 数据源、7799 字段 | 任意文档 + 22 个代码项目 |
| 数据库 | 9 种数据库统一管理 | SQLite + ChromaDB |
| Schema | Layer 0/1/2 三层标准 | 无固定 schema |
| AI | DeepSeek SQL 助手 | RAG 通用问答 + 代码语义搜索 |
| 部署 | Fossil + 多微服务 | 单文件 Flask |
| 容错 | 无 | 断点续传（目录级 + 文件缓存） |
