## 0. 要收回什么、不要动什么

| 端口 | 服务 | 公网 |
|------|------|------|
| **5210** | Tatha 演示栈 | **收回** |
| **5220** | DemoPeter 知识库 UI | **收回** |
| **3210** | am-gateway | **收回** |

| 端口 | 作用 | 公网 |
|------|------|------|
| **22** | SSH | **保留** |
| **80** | Nginx：PlanetX + `/circle/` 会场（阶段 1 入口） | **保留** |
| **443** | 以后 `circle.genz.ltd` | **有则保留；没有不必现加** |
| **5211** | 格契内核 | **不要新开放**（进程可听 `0.0.0.0`，靠安全组挡住） |

安全组是白名单：删掉「允许」之后，公网打这些口应超时或拒绝，**不是** 200。进程可以仍在机内听着，本机 `curl 127.0.0.1:5210` 仍可能通——那不算公网暴露。

**不要**为了收口去 `systemctl stop` 演示栈或改 nginx `/circle/`。补丁 3 只改安全组。

## 1. 改之前先测一次（本机终端，不要在云主机上测）

在 Mac 上执行（从云机 `curl 127.0.0.1` 不能证明公网已封）：

```bash
curl -sS -o /dev/null -w "5210 %{http_code} %{errormsg}\n" --connect-timeout 8 http://14.29.216.219:5210/v1/region
curl -sS -o /dev/null -w "5220 %{http_code} %{errormsg}\n" --connect-timeout 8 http://14.29.216.219:5220/
curl -sS -o /dev/null -w "3210 %{http_code} %{errormsg}\n" --connect-timeout 8 http://14.29.216.219:3210/health
curl -sS -o /dev/null -w "circle %{http_code}\n" --connect-timeout 8 http://14.29.216.219/circle/
```

改前：前三行常为 **200**（这就是补丁 3 要收的洞）。`circle` 应为 **200**。把这四行抄下来，改完对照。

## 2. 打开安全组（两条路，任选一条）

控制台区域选 **深圳**（与云主机同一地域）。

**路 A（最快，你已经在这台机详情页）**

1. 弹性云主机 → `ctyun`  
2. 顶部页签点 **「安全组」**（基本信息 / 云硬盘旁边）  
3. 看到已绑定组（多半是 `Sys-default`）→ 点安全组**名称**进入规则

**路 B（网络控制台）**

1. 产品 → **网络 / 虚拟私有云**  
2. 左侧 **访问控制 → 安全组**  
3. 打开该组 → **入方向规则**

官方删规则说明：[删除安全组规则](https://www.ctyun.cn/document/10000023/10105182)

若该组还绑了**别的云主机**：先停，不要在共享组上删规则。应克隆/新建专用组（只绑 `ctyun`）再改。只有这一台可以继续改 `Sys-default`。

---

## 3. 看入方向，按三种样子处理

只改 **入方向**。出方向（云主机访问外网）不要动。

### 样子 1：三条独立规则（最常见）

协议 TCP，端口分别是 `5210`、`5220`、`3210`，源地址常为 `0.0.0.0/0`。

对这三行各点 **删除** → 确定。一次删一条，删完再下一条。

### 样子 2：一段端口范围盖住了它们

例如 `3000-6000`、`1-65535`、`5000-5300`。

**不要整段删掉**（可能连 22/80 一起没了）。应：

1. 记下该段的源地址、优先级  
2. **删除**这一段  
3. **立刻补回**仍需要的口：TCP `22`、`80`，若原来有 `443` 也补回；源地址仍用 `0.0.0.0/0`（或你原来的网段）  
4. **不要**再加 5210 / 5220 / 3210 / 5211

### 样子 3：一条「全部协议 / 全部端口」

这是最大的洞。处理同样子 2：删掉全放行，只加回 **22 + 80**（+ 已有的 443）。

## 4. 改完自检（控制台）

入方向允许列表里：

- **没有** 5210、5220、3210  
- **没有** 5211  
- **仍有** 22、80  
- 443：有则留，没有可等切 `circle.genz.ltd` 再加

## 5. 改后再测（仍在 Mac）

再跑 §1 那四条 `curl`。

| 口 | 期望 |
|----|------|
| 5210 / 5220 / 3210 | **不是 200**。常见：`000` + Connection timed out / Connection refused |
| `http://14.29.216.219/circle/` | 仍 **200** |
| `ssh root@14.29.216.219` | 仍能上 |

若三端口仍 200：规则没保存、改错了安全组、或有第二条组仍放行。回到 §2 看这台机绑定的**每一个**安全组。

若 `/circle/` 也挂了：误删了 80。按 §3 样子 2 把 TCP 80 加回入方向，源 `0.0.0.0/0`。
