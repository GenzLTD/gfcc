## 0. 一句话

主持人继续持 `ETHOS_AUTH_SECRET` 签发身份；testers **点一条深链入场**，不再把整段 JWT 往微信里贴。页面始终没有注册表单。

国际闭门场的同类物：Loomio「管理员发一次性邀请链接」、Pol.is embed「url-token / XID 寄出带身份的 URL」、Decidim 私密过程「导入邮箱 → 邀请邮件」。我们只做其中**最小切片**：一次性兑换码 + 已有 HS256 会话。

---

## 1. 为什么做 / 为什么不做成注册

| 要解决 | 不在范围内 |
|--------|------------|
| 微信/短信截断或贴错长 JWT | 邮箱 / 微信 OAuth、密码、验证码登录 |
| 查询串、访问日志、Referer 泄漏完整票 | 公网「填 sub 就出 JWT」的签发 API |
| 一人一 `sub` 仍由主持人报名表保证 | 「申请加入」待批、人口普查/证件核身 |
| 粘贴 JWT 作为**备用**仍可用 | 嵌入 Pol.is、复制 Loomio 源码 |

无账号时 JWT 的 `sub` 就是身份（票 = 身份）。签发权必须留在密钥持有者环境。兑换码是**能力令牌**：猜不到码就换不到票；猜到并使用一次即作废。这不是自助开号。

组织者仍是「持有效票之后建圈的那个 `sub`」，不是注册出来的角色。

## 4. 数据模型

新建库文件（不要写进 Dual `memory_records`）：

`services/gfcc_kernel/data/circle_invites.db`（或与现有 store 同目录、独立文件）。

```sql
CREATE TABLE IF NOT EXISTS circle_invites (
  code_hash TEXT PRIMARY KEY,   -- SHA-256 hex(utf-8 兑换码)，库泄漏不能直接兑换
  sub       TEXT NOT NULL,
  exp       INTEGER NOT NULL,   -- unix 秒，与 JWT exp 对齐（默认 30 天）
  redeemed_at INTEGER,          -- NULL = 未用
  created_at  INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_circle_invites_sub ON circle_invites(sub);
```

- 兑换码：Crockford Base32（或等价「无易混字符」字母数字），**16 字符**，`secrets.token_bytes` 生成，约 80 bit。
- 同一 `--subs` 跑两次：旧码可保留至过期，或按 sub **作废未兑换旧码再写新码**（实现选一种，测试写死；推荐作废未兑换旧码，避免一人多条有效链）。
- 进程内存 dict **不合格**（与「重启丢圈」同类，邀请会先于场次发出）。

## 5. API

前缀仍是 `/circle/`（不占 `/v1/`）。

### `POST /circle/api/redeem`

无 `Authorization`。

请求：

```json
{ "code": "0123456789ABCDEF" }
```

| 条件 | HTTP | body |
|------|------|------|
| 码有效且未兑换 | 200 | `{ "sub": "...", "token": "<HS256 JWT>" }` |
| 缺字段 / 码格式非法 | 400 | `{ "detail": "invalid code" }` |
| 未知或已过期 | 404 | `{ "detail": "invite not found" }` |
| 已兑换 | 410 | `{ "detail": "invite already used" }` |

200 时：把 `redeemed_at` 写上；签发的 JWT 与现脚本相同（`sub`/`tier`/`iat`/`exp`，HS256）。  
410 文案可提示：向主持人再要一条，或粘贴备用令牌。

**限流**：同一来源 IP 兑换失败合计 ≥ 20 次 / 10 分钟 → 429。防止扫码。成功兑换不计入暴力阈值也可（实现自定，测试覆盖失败路径）。

**不要**提供 `GET /circle/api/redeem?code=`（码进访问日志）。

其余 `/circle/api/me|create|join|leave|propose|ack|status` 行为不变，仍要 Bearer。

## 6. CLI（`issue_persona_tokens.py`）

新增参数：

| 参数 | 含义 |
|------|------|
| `--invite-base URL` | 会场根，如 `https://circle.genz.ltd/circle/`（子域未绿前可用 IP HTTP；无则只发码不拼 URL） |
| `--invite-days` | 邀请与 JWT 有效期，默认与 `--days` 相同（30） |

输出：

- 终端每行：`sub \t invite_url \t code`（无完整 JWT）。
- `--out` JSON **允许**字段：`sub`、`invite_code`、`invite_url`、`token`（备份）、`exp`。  
- `--out` JSON **禁止**字段：`secret`、`ETHOS_AUTH_SECRET`。现有写入 `secret` 的行为一并删掉。
- 文件 `chmod 600`。

`invite_url` 形如：`http://14.29.216.219/circle/?i=<code>`（`code` 需 `urllib.parse.quote`）。不要把 JWT 放进 query/hash。

签发仍拒绝重复 `--subs`。

## 7. 前端（`circle.html`）

1. 解析 `i`、`c`（`c` 逻辑保持：填入圈号框）。
2. 若有 `i`：禁用入场按钮期间调用 redeem → 写入 `gfcc_circle_token` → 调 `me` → `replaceState` 去掉 `i`，保留 `c` 与 path。
3. redeem 410/404：显示错误，**落下粘贴令牌框**（备用）。
4. 无 `i`：行为与现在一致（粘贴 JWT）。
5. 入场文案改一句：优先邀请链接；令牌仅备用；没有注册。
6. 不要把 `i` 或 JWT 写进 `localStorage`；不要把码拼进分享用的「把这条链接发到群里」（组织者分享链仍只带 `?c=`）。
