# MVP 内测人员征集与测试手册

> **地位**：招募 + 操作手册，面向 MVP 内测的**真实参与者**（真人共同体，不是开发联调）。  
> **目标**：征集 **4 人以上**真人，部署至**天翼云**，完成注册试用与一场共识测试。  
> **对照**：[MVP 内测资源配置清单](MVP_资源配置清单.md)（G0–G6 开工门禁，人齐后逐项评估）  
> **状态**：**招募中**。流程：人齐 → 天翼云部署 → 门禁评估 → 开测。  
> **记录日期**：2026-08-25。

## 一、这是什么？为什么要参加？

**格契（GFCC）** 是把「记得住、协商得了、贡献兑得现」做成可交付体系的社区牵引力层：AI 不抢方向盘，共同体自己定方向，系统负责把共识、贡献、成长记录在案。

参加内测 = 作为**真实成员**走进一个 AI 共同体，体验一场「提议 → 共议 → 达成共识 → 兑现贡献」的完整闭环。内测不只是点按钮，是在验证这套体系对真人是否真的可用。

## 二、征集目标

| 项 | 要求 |
|----|------|
| 名额 | **4 人以上**（契约下限 3，推荐 4 人：圈主 / 对端 / 旁观样本 / 主理） |
| 身份 | 真实个人，**不是**开发联调账号、不是机器人 |
| 承诺 | 参加至少 1 场 60–90 分钟同步会（场次时间报名后协调） |
| 地点 | 线上 + 天翼云测试环境（地址见第四节） |
| 门槛 | 无需编程经验；会点网页、会发消息即可 |

## 三、席位说明（报名时认领一个）

| 席位 | 内测中要做什么 | 适合 |
|------|----------------|------|
| **A 圈主** | 建圈、提一个真议题、写一条可被引用的记忆、认定他人贡献 | 想主导、想张罗 |
| **B 对端** | 当第二 party、认真看议题、本人亲自点 ack | 想深度参与讨论 |
| **C 旁观样本** | 先旁观一场，再凭实际参与痕迹升级为 participant | 想先看看再决定 |
| **D 主理** | 把承诺的贡献兑现掉，留下可查的兑现记录 | 想验证「兑现」这条链 |

> 每人一次只认领一个席位；A 可兼 D。开发/管理员可以值班（端侧支撑），但**不能**顶替 A/B/C 席位。

## 四、测试环境与注册（天翼云已部署）

**天翼云测试环境地址（2026-08-25 已通）：**

| 入口 | 地址 | 用途 |
|------|------|------|
| 知识库 UI | `http://14.29.216.219:5220/` | **推荐入口**：文档上传、RAG 问答（浏览器直接可用） |
| 中央大脑 | `http://14.29.216.219:5210/v1/region` | 区域定价（无鉴权探活） |
| 记忆网关 | `http://14.29.216.219:3210/health` | 健康检查 |

> 未绑域名（ICP 备案前走 IP + 端口）；如遇浏览器「不安全」提示属正常，用无痕窗口访问。

流程：

1. **注册**：`POST /v1/auth/register`，提交邮箱 + 密码（≥6 位），返回演示令牌（Phase 1 演示桩，未对接真实认证）。
   ```bash
   curl -X POST http://14.29.216.219:5210/v1/auth/register \
     -H 'Content-Type: application/json' \
     -d '{"email":"<你的邮箱>","password":"<≥6位密码>"}'
   # 预期：{"ok":true,"message":"注册成功（演示用，未对接真实认证）","token":"demo-token-..."}
   ```
2. **登录**：`POST /v1/auth/login`，同字段，返回演示令牌。
3. **注意事项**：
   - 演示令牌只做格式校验，**不能**通过记忆网关验签；内测场次中的记忆/共识操作由**主持人统一发放有效令牌**，参与者无需自己签发。
   - 知识库 UI（5220）浏览器直接可用，不依赖令牌。
4. **可试用能力**（2026-08-25 实测）：
   - 知识库：在 5220 UI 上传自己的文档，发起 RAG 问答（AI: deepseek）。
   - 记忆：说一句话让系统记住；再问它是否还记得（场次内由主持人带跑）。
   - 共识：按第五节的剧本走完一场「提议 → ack → 共识 → 兑现」。

> 说明：当前部署的 agentmemory 引擎处于**无模型模式**（未挂 embedding 模型），记忆可写入、检索可用但语义相似度检索为降级状态；语义检索增强不阻塞内测验收。

## 五、一场内测怎么做（60–90 分钟）

主持人带跑，参与者只需照做：

1. **建圈入座**：A 建一个真实议题圈（不是「测试圈」空转），B 加入，C 旁观。
2. **提议共议**：A 提出一个真议题（如「本月团队如何分工」「下一版先做哪个功能」），写清楚背景与提案。
3. **共识达成**：A、B 各自**本人**点 ack（AI 不能代点、不能只为自己认定贡献）→ 系统记录 `consensus_verified`。
4. **留下痕迹**：下一个议题/行动引用上一步的共识记录（证明「记得住」）。
5. **兑现贡献**：A 认定 B 的贡献；A 或 D 把承诺兑现掉，系统记录兑现轨迹。
6. **升级（可选）**：C 凭实际参与证据升为 participant（不是管理员直接拨权限）。

**本场不做**：申诉、解散圈子、改规则、选项组 UI、链上锚定。

## 六、反馈与评估

| 项 | 说明 |
|----|------|
| 反馈方式 | 场次后 10 分钟问卷 + 自由发言；也可场后随时在群内提 |
| 反馈重点 | 界面是否看得懂、流程是否顺畅、共识/兑现记录是否可信、哪里想摔键盘 |
| 评估 | 五条判据（记得住 / 协商得了 / 贡献兑得现 / 人往高处走 / AI 不抢戏）须能在库里指出对应记录，才算本场内测通过 |
