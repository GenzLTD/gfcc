## 一、这是什么？为什么要参加？

**格契（GFCC）** 是把「记得住、协商得了、贡献兑得现」做成可交付体系的社区牵引力层：AI 不抢方向盘，共同体自己定方向，系统负责把共识、贡献、成长记录在案。

参加内测 = 作为**真实成员**走完一场「提议 → 共议 → 达成共识 → 兑现贡献」。验证方式是库里能指出记录 id（人 ↔ 账号 ↔ 记录），**不是**回放腾讯会议，也不是测人格测评好不好玩。

## 五、一场内测怎么做（60–90 分钟）

主持人带跑，参与者只需照做：

1. **建圈入座**：A 建一个真实议题圈（不是「测试圈」空转），B 加入，C 旁观。
2. **提议共议**：A 把商量结果写成一句真议题（如「本月团队如何分工」）。
3. **共识达成**：A、B 各自**本人**点确认（AI 不能代点、不能只为自己认定贡献）→ 系统记录 `consensus_verified`。**本场阈值**：默认 **85**（`CONSENSUS_THRESHOLD`，circle 可在建圈时自定）；AI 证据只作辅证，**不得作为唯一依据**。
4. **留下痕迹**：下一个议题/行动引用上一步的共识记录（证明「记得住」）。
5. **兑现贡献**：A 认定 B 的贡献（`/circle/api/attest`，不能只为自己认定）；A 或 D（steward+）把承诺兑现掉（`/circle/api/fulfill`），兑现成功自动在 B 画像 mint 一条 `contribution` evidence 轨迹（兑现入口已打通）。
6. **升级（可选）**：C 凭实际参与证据升为 participant（`/circle/api/promote`，须带证据记录 id，**无证据一律拒绝**，禁止只拨 admin）。

**本场不做**：申诉、解散圈子、改规则、选项组 UI、链上锚定。

**实现约束（值班端必知）**：内核 SQLite 持久化 `memory_records` / `signal_log` / `circle_flow.db`（圈·共识·地板，重启不丢场次态）；**identity / contribution / session 仍在内存**。场次结束前必须把验收 id 抄出或导出。未勾完清单 G6 只做桌面演练，不开系统内测。

## 六、反馈与评估（如何验证）

验证对象是 **报名真人 ↔ 令牌 `sub` ↔ 记录 id**，不是会议回放。

| 项 | 说明 |
|----|------|
| 反馈方式 | 场次后 10 分钟问卷 + 自由发言；也可场后随时在群内提 |
| 反馈重点 | 是否知道自己在点什么、确认是否像「签字」、记录是否可信、哪里想摔键盘 |
| 评估 | 五条判据须能在库里指出对应记录，口径见 [MVP 资源配置清单](MVP_资源配置清单.md) §5 |

值班端当场核对：圈成员 `sub` = A/B；两条 ack 的 `sub` 是这两个真人；后续记录 `refs` 指向该共识 id；认定/兑现可查。对不上即失败。
