## 0. 一句话

入座者**轮流拥有发言权（地板）**；只有地板持有者能提交下一条拍板句。全员 ack 达成后，地板按入座顺序交给下一人。本人确认、一次一条共识、邀请深链**都不改**。

这不是 Loomio 讨论线程（不搬 AGPL）。过程感来自「现在轮到谁写拍板」，不是自由发言墙。

---

## 1. 为什么做 / 为什么不做成举手或论坛

| 要解决 | 不在范围内 |
|--------|------------|
| 与会者入座后只有表决、没有「轮到我提议」 | 举手排队、意图箱、自由评论 |
| 一次一条时提交框收起，别人无法表达下一意图 | 并行多条拍板、选项组 UI |
| 90 分钟场若只靠视频商量，系统像表决器 | 腾讯会议代替 ack；AI 代写拍板 |
| 组织者离场后全场不能再提议（旧 bug）/ 人人同时可提议（易抢麦） | 申请加入、改 JWT 角色冒充地板 |

拍板仍是要全员 ack 的那一句。地板只决定**谁有权提交**这一句。旁观仍不能提议、不能 ack（未入 parties）。

## 3. 目标行为（一场 3 人）

入座顺序：A（建圈，先有地板）→ B → C。

1. A 有地板，写拍板 1；B、C（及当时在座的 parties）本人 ack → `consensus_verified` → 地板交给 B。
2. B 写拍板 2；全员 ack → 地板交给 C。
3. C 写拍板 3；全员 ack → 地板交回 A。
4. 有未达成拍板时：提交框收起（一次一条，现逻辑保留）；地板**不**在 ack 过程中轮转。
5. 旁观只看；未入座 403 propose。
6. 非地板入座者：能 ack（若在 parties 里）、能看到队列提示，**不能**提交拍板。

主持人（场外职责）可以入座当 participant；未进该条 parties 则不必 ack——与圈 `3f19cd62` 口径相同。下一轮若轮到他持地板，他才能写新拍板。

## 4. 数据与规则

圈对象增加：

```text
floor_sub: str | null   # 当前地板；无人在座时 null
```

成员顺序 = `members` 数组顺序（建圈者第一，随后 `join` 追加）。`joined_at` 仅作展示，轮询不要另排序。

### 4.1 建圈

`create`：`floor_sub = organizer`（与 `created_by` 相同）。

### 4.2 入座 / 退场

- `join`：**不**抢地板。
- `leave`：若 `floor_sub == 离开者`：
  - 在座剩余 ≥1：`floor_sub = 下一位`（见 4.4，以离开者为「当前」，在**剩余**成员里取下一位）。
  - 否则 `floor_sub = null`。
- 离开即放弃本轮写拍板的机会。进行中的拍板仍由当时的 parties ack。

### 4.3 达成后轮转

`acknowledge` 成功且该提案 **刚刚** 变为 `consensus_verified` 时：

- 若 `circle.floor_sub == proposal.proposer_sub`（地板仍在提议人身上）：执行一次 `advance_floor`。
- 若提议人已 leave、地板已在 4.2 交给别人：**不要再进一位**（避免 B 还没写就被跳到 C）。

`proposal` 必须带 `proposer_sub`（现 `propose(..., proposer_sub=sub)` 已有则复用；没有则补上并写测试）。

不要在 `propose` 时转地板（未 ack 先轮转会乱）。

### 4.4 下一位

```text
next_floor(members, current_sub) -> sub | null
  若 members 空 → null
  若 current_sub 仍在 members：取其下标 i，返回 members[(i+1) % n].sub
  若 current_sub 已不在（已 leave）：返回 members[0].sub
```

仅一人在座：`(i+1)%1` 仍是自己；propose 仍因「不足 2 人」400。

### 4.5 一次一条（不变）

未 `consensus_verified` 的拍板 ≥1 时，前端收起提交框。后端 propose：若该圈已有非 verified 提案 → **400** `pending proposal exists`（现在若只靠前端收起，必须补后端闸，防抢麦）。

## 5. API

前缀仍 `/circle/`。无新公开签发。`redeem` / `me` / `join` / `leave` / `ack` 除 §4.3 外不变。

### `POST /circle/api/propose`

在现有「已入座、≥2 人」之上增加：

| 条件 | HTTP | detail（稳定字符串，测试写死） |
|------|------|------|
| 未入座 | 403 | `only seated members may propose` |
| `sub != floor_sub` | 403 | `not your floor` |
| 圈内已有未 verified 拍板 | 400 | `pending proposal exists` |
| 在座 < 2 | 400 | `need at least 2 seated members before proposing` |

成功：行为同现网（propose + score，`parties = 当前 members`，`kind: proposer_basis`）。

### `GET /circle/api/status`

`circle` 内含 `floor_sub`。建议同时返回：

```json
"floor_next_sub": "<下一位 sub 或 null>"
```

用 4.4 对**当前** `floor_sub` 预览（未达成前只是预告；达成后才真正前进）。

无 GET 改地板接口（禁止管理员拨地板冒充轮询）。

## 7. 前端（`circle.html`）

1. 状态卡显式：**当前发言权：{floor_sub}**；若 `me == floor_sub` 加「轮到你写拍板句」。
2. 提交卡显示条件：`isSeated && pendingCount==0 && me==floor_sub`。
3. 已入座但非地板且无 pending：显示说明「现在轮到 X；本条达成后轮到 {floor_next_sub}」。不要空白。
4. 旁观：仍无确认、无提交、无地板。
5. 组织者分享链仍只带 `?c=`，不含令牌。
6. 文案避免「仅主持人可发言」；应写「按入座顺序轮流提交拍板」。

## 8. 测试（新文件或扩 `test_circle_web.py`）

最少：

1. 建圈后 `status.circle.floor_sub ==` 建圈者。
2. A 地板，B propose → **403** `not your floor`。
3. A propose + A/B ack → verified 后 `floor_sub == B`。
4. B propose + 全员 ack → `floor_sub == A`（两人圈循环）。
5. 三人：A→B→C→A。
6. 未 verified 时第二人 propose → 400 `pending proposal exists`（即使是地板本人连提两条也拒绝）。
7. 地板持有者 leave（无 pending）：`floor_sub` 为下一位在座者。
8. 提议人 leave（有 pending）：其余 party 仍可 ack；verified 后地板**不是**再跳一格导致下下家（对 4.3 写死期望）。
9. 旁观 propose → 403；旁观 ack → 仍 400 not a party。
10. 回归：邀请 `redeem`、粘贴 JWT `/me`、join 幂等。

本地 pytest 全绿后再上云。
