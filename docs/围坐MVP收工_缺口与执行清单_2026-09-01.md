## 3. 建议执行顺序

```
① 确认备案（决定链接用域名还是 IP）
② 启用 R1 日志脱敏（A1，一个 nginx 配置动作）
③ 天翼 git pull 到 b21ee33 + restart + 冒烟（B1，或保守保持 833ee54）
④ 天翼签发真人邀请（B3，--invite-base https://circle.genz.ltd/circle/）
⑤ 60–90 分钟场次：建圈→入座→旁观→拍板→本人确认→引用→兑现→升级（C4）
⑥ 值班核对五条判据库 id，回填 G1/G2/G3/G6（C1–C3、C5）→ 宣布 MVP 内测通过
⑦ 文档回写：施工单状态（A3）、邀请深链验收 C/D/E、测试手册、新场次纪要
```

## 4. 需 Windows 侧拍板的决策点

1. **B1 是否拉齐代码**：天翼 `833ee54` 已 16/16 冒烟通过，但落后 Gitee 10 commit（含 kernel 功能改动与文档回写）。拉齐 = 场次前多一次重新冒烟；不拉齐 = 文档比现网快的口径问题。
2. **A2 备案**：`circle.genz.ltd` 是否已过网站备案（决定真人链接走域名还是 IP）。
3. **C2 真人招募**：3 人下限 / 4 人推荐，何时人齐由招募方定；人未齐期间保持无限期等待，禁止联调账号凑数。

## 5. 遗留边界（场次内不做，供知情）

- 申诉 / 解散圈子 / 改规则 / 选项组 UI / 链上锚定 / 开通会员。
- identity/contribution 数据仍在内存（无兑现持久化表）：**散会前抄 id**，否则重启即失。
- 多 worker / 分片场景未验证（当前单进程）。
- 邀请深链为「一次性兑换码 + 既有 HS256 会话」，**不是**账号体系；邮箱/SSO 是独立史诗。
