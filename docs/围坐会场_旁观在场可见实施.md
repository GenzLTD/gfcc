## 0. 一句话

旁观要有**服务端在场**：点「只旁观 · 先只看」必须登记 `watchers`，`/status` 带旁观名单，A/B 页面看得到。旁观仍 **不入座、不进 `parties`、不能提议、不能 ack**。

## 0.1 定性（已拍板）

| 判定 | 口径 |
|------|------|
| 是不是 500/401 回归 | **不是**。拍板、双确认、地板轮转按设计 |
| 是不是围坐设想缺口 | **是**。清单 C 旁观样本要「在场可感」；现网旁观只改 C 自己的浏览器 |
| 今晚要不要热修 | **不要**。守则：场次中不重启内核 |
| 错误修法 | 让 C `join` 入座来「被看见」→ 下一条拍板变成三方 ack，破坏旁观剧本 |

08-28 修的是 C **自己**看不见确认按钮（问题 3），从未做「A/B 能看见谁在听」。

## 0.2 本单在初期设计里占哪一块（不要扩写）

初期剧本（须知 / 清单）是一场 6 步：A 建圈、B 入座、**C 旁观**、拍板双确认、引用、兑现、可选升级。本单**只补第 3 步的在场可感**——C 旁听本来就在设计里，现网漏了服务端登记，A/B 看不见。

**不要**借这张单去对齐整场 MVP：

- 不顶 G2（tester-b / tester-c 仍是占位，勾不上具名真人）
- 不做引用 / 兑现 / promote（剧本后半段，API 已有、测试方案未跑）
- 不改全员 ack、不把旁观并进 `parties`

对照长文放决策备忘与清单，不复制进本单。做完旁观可见，仍是冒烟场，不是 G1–G6 通过。

## 2. 为什么做 / 为什么不做成别的

| 要解决 | 不在范围内 |
|--------|------------|
| A/B 不知道圈里有没有人在听 | 把旁观并进 `members` / `parties` |

## 3. 决策（动笔即按此）

| # | 决策 | 选定 | 理由 |
|---|------|------|------|
| ① | 旁观与入座 | **两套名单**：`members` ≠ `watchers` | 入座才进 parties；旁观只在场 |
| ② | 登记时机 | 点「只旁观」→ `POST /circle/api/observe` | 与现按钮对齐；不能再只改前端 |
| ③ | 落库 | 同文件 `circle_flow.db` 新表 `circle_watchers` | 重启仍能看见谁在听；不进 Dual / 邀请库 |
| ④ | 已入座再点旁观 | **400**（已在席，用离场再旁观） | 避免一人同时在两套名单 |
| ⑤ | 旁观后再入座 | `join` **幂等入座**，并**从表摘掉**该 `sub` 的 watcher | 升级路径：先看再坐，不留幽灵旁观 |
| ⑥ | 离开旁观 | `POST /circle/api/unobserve`；关标签不保证立刻消失 | v1 不做心跳；已知缺口见 §7 |
| ⑦ | 退出按钮 | **已入座 → `/leave`；仅旁观 → `/unobserve`** | 现网「退出」一律打 leave，旁观会 400，C 清不掉在场 |
| ⑧ | 重复点旁观 | **幂等 200**（已在 watchers 则刷新 `observed_at` 或原样返回） | 误点两次不应变 400 |
| ⑨ | 深链 `?c=` | **只预填圈号，不自动 observe** | 打开链接 ≠ 登记在场；仍须点「只旁观」 |
| ⑩ | A/B 看见谁 | **同一份 `watchers`**，不按 organizer 过滤 | `status` 本来就原样返回；jason 与 tester-b 都是 3s 轮询，不必给 A 单独接口 |
| ⑪ | 组织者管旁观 | **v1 不能请旁观离场、不能禁看** | 本单只做在场可见，不做会场警察 |
| ⑫ | A/B 自己退出 | `leave` 只摘自己的 member；**不清**别人的 watcher | jason 先走，tester-c 仍可在旁观名单里，直到 C 自己 unobserve |
| ⑬ | 确认文案 | 有旁观时禁止再写含混的「全员确认」 | tester-b 最容易把旁观当成第三 party；改成「入座成员确认」或列出 `parties` |

HTTP：**只加路径与 `status` 的 additive 字段**，不改 `create` / `join` / `propose` / `ack` 的既有状态码语义。

## 5. 目标行为（一场 3 人）

A 建圈入座 → B 入座 → C 点旁观（不入座）。

1. A/B 刷新后状态卡：**已入座 2 人** + **旁观 1 人（tester-c）**。
2. C 无确认按钮、无拍板框；ack → 400 `not a party`；propose → 403（未入座 / 非地板）。
3. A 提议、A+B 双确认 → `consensus_verified`；`parties` 仍是 `[jason, tester-b]`，**不含 C**。
4. C 再点入座 → members 3 人、watchers 不再含 C；**之后**新拍板 `parties` 才含三人。
5. 重启内核 → 同一 `status` 仍能看到该旁观（v1 已登记且未 unobserve）。

页面文案建议：成员药丸保持原样；其下增加一行「旁观：」+ 弱样式药丸（不要标成地板/组织者）。已入座人数与旁观人数分开写，勿把旁观算进「已入座 N 人」。

### 5.1 jason（A 组织者）与 tester-b（B 参与者）— 本单真正要改的是文案，不是权限

现网入座后 **A 和 B 几乎同一套 UI**：都轮询 `/status`、都看到成员药丸和分享链接；差别只有组织者药丸「· A」、地板才出现拍板卡、`parties` 里才有确认键。旁观名单应对 **A/B 渲染完全相同**，不要给 jason 做「主持仪表盘」。

| 角色 | 本单要有的 | 本单不要有的 |
|------|------------|--------------|
| **jason（organizer）** | 3s 内看到「旁观：tester-c」；分享链接仍是同一条 `?c=`（打开后对方自选入座或旁观）；建圈成功提示可补一句「旁观会出现在状态卡，不参与确认」 | 踢旁观、禁看、旁观专用第二套链接、因 C 在场就改变 `parties` / 地板 |
| **tester-b（participant）** | **同样**看到旁观行；确认进度分母仍是 `parties.length`（今晚是 2）；「需确认」名单不含 C；有拍板卡时仍只在自己持地板时出现 | 等 C 点确认才算达成；把旁观药丸点成地板/组织者；B 比 A 少看旁观名单 |

**B 视角是本单的验收硬点。** 今晚缺口是「A/B 都看不见 C」；修完后的新坑是「B 看见 C 之后以为要三方确认」。现网会把人绕进去的句子：

- 提交成功：「等待**全员**本人点确认」
- pending 条：「**全员**确认完……才能提交下一条」
- 拍板框描述：「**全员**各自确认后，发言权交给下一位」（`circle.html:161` 静态文案，同一替换范围内）

有 `watchers.length > 0`（或一律改掉，更干净）时改为：「须 **入座成员** 本人确认（旁观不点头）」；拍板卡下「需确认：」继续只列 `parties`。进度条 `acks/parties` 不要改成 `acks/(members+watchers)`。

pytest / 冒烟必须打 **tester-b 的 GET /status 与页面**，不能只验 jason。

A 或 B `leave` 后：对方仍在座、旁观仍在；圈保持 `active`。不要在 jason 退场时级联清 testers 的 watcher。

## 6. 数据模型（最小）

同库新表（名称可微调，语义不可变）：

```sql
CREATE TABLE IF NOT EXISTS circle_watchers (
    circle_id   TEXT NOT NULL,
    sub         TEXT NOT NULL,
    observed_at TEXT NOT NULL,
    left_at     TEXT,
    PRIMARY KEY (circle_id, sub)
);
```

- 当前在场：`left_at IS NULL`。
- `GET /status` 形状（additive）：

```json
{
  "circle": { "...members, floor_sub..." },
  "watchers": [{ "sub": "tester-c", "observed_at": "..." }],
  "proposals": [],
  "floor_sub": "...",
  "floor_next_sub": "..."
}
```

`watchers` 缺省 `[]`。旧客户端忽略未知字段仍可用。

鉴权：observe / unobserve / status 均须 Bearer；无令牌 401。未知圈 400/404 与 `join` 对齐。
