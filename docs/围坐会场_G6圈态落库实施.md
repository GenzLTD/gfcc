## 0. 一句话

把「圈 / 共识 / 地板」三块会务状态从进程内存搬到 SQLite，让 **restart 不再清场**、本场不只是桌面演练。

地板不是第三张独立业务表：它是 `circles.floor_sub`，轮转逻辑仍是现成的 `next_floor()` / `advance_floor()`。

当前 `restart → 全空 → 上一场作废` 是 **G6 没做的容忍态**，不是设计目标。本单做完后，重启应恢复上一场（圈在、成员在、地板在、已 verified 提案在）。

## 0.1 两个决策（已拍板，动笔即按此）

| # | 决策 | 选定 | 理由 |
|---|------|------|------|
| ① | 库文件 | **独立库** `data/circle_flow.db` | 会务过程数据 ≠ Dual（`memory_records`）≠ 入场票（`circle_invites.db`）。下一刀 `refs` 才写 Dual。**圈表与提案表必须同文件**，否则决策 ② 的同事务做不到。 |
| ② | ack 达成 vs 地板轮转 | **同事务** | 现 `api_ack` 两段式（先 `consensus.acknowledge` 达成，再 `circle.advance_floor`）。崩在中间最多地板不轮转，leave/join 可校正，但会务账对不齐。本单把两步写进**同一 SQLite 事务**。 |

HTTP 路径、请求/响应 JSON、`propose`/`ack`/`status` 状态码**不变**。`circle_web.py` 允许为同事务做**最小改动**（`with flow.transaction()` 包住现有两段）；不要为了「一行不改」把事务拆开，也不要把 circle 逻辑塞进 `ConsensusAdapter`。

环境变量：`CIRCLE_FLOW_DB`（覆盖默认路径；测试用临时库，不污染生产）。根 `.gitignore` 的 `data/` 已忽略该文件。

## 3. 目标行为

1. 建圈 → 入座 → 地板拍板 → 全员 ack → `consensus_verified`，地板交给下一位（现轮询语义）。
2. **重启内核**（kickstart / `systemctl restart`）。
3. 同一令牌 `GET /circle/api/status?circle_id=`：圈还在、成员还在、`floor_sub` 是达成后的那一位、verified 提案还在、acks 还在。
4. `dissolve`：行还在，`status=dissolved`，`dissolved_at` 有值；**不 DELETE** 圈/提案/ack（对齐契约「dissolve 不删历史」；Dual 记录本单仍不写）。
5. `leave`：该人从 `circle_members` 消失（与今天从 `members` 数组摘掉同形）；若持地板则 `floor_sub` 按 `next_floor` 更新并落库。

无旧场迁移：内存态本来就会随重启消失，本单上线后**新场次**开始持久化。不要写「把幽灵 dict 导进 sqlite」的脚本。

## 4. 数据模型

新建 `services/gfcc_kernel/data/circle_flow.db`（与 `circle_invites.db` 同目录、**不同文件**）。不要写进 `memory.db`。

抄 `invites.py`：`CREATE TABLE IF NOT EXISTS` + 索引、`with connect()` 事务、模块单例 `get_store()`、`CIRCLE_FLOW_DB` 覆盖。`PRAGMA foreign_keys=ON`。

```sql
CREATE TABLE IF NOT EXISTS circles (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  parent_id    TEXT,                 -- 预留嵌套；本单不实现分组软件
  status       TEXT NOT NULL,        -- forming / active / paused / dissolved
  created_by   TEXT NOT NULL,
  created_at   TEXT NOT NULL,        -- 与现 adapter 相同的本地时间串
  dissolved_at TEXT,
  floor_sub    TEXT                  -- 无人在座时 NULL
);

CREATE TABLE IF NOT EXISTS circle_members (
  circle_id    TEXT NOT NULL REFERENCES circles(id),
  sub          TEXT NOT NULL,
  role         TEXT NOT NULL,
  builder_tags TEXT NOT NULL DEFAULT '[]',  -- JSON 数组
  joined_at    TEXT NOT NULL,
  PRIMARY KEY (circle_id, sub)
);
CREATE INDEX IF NOT EXISTS idx_circle_members_circle ON circle_members(circle_id);

CREATE TABLE IF NOT EXISTS proposals (
  id             TEXT PRIMARY KEY,
  circle_id      TEXT NOT NULL REFERENCES circles(id),
  subject        TEXT NOT NULL,
  issue_id       TEXT,
  created_by     TEXT NOT NULL,
  status         TEXT NOT NULL,
  score          REAL,
  score_evidence TEXT NOT NULL DEFAULT '[]',  -- JSON 数组
  parties        TEXT NOT NULL,               -- JSON 数组，至少 2 人
  created_at     TEXT NOT NULL,
  verified_at    TEXT                         -- 进入 consensus_verified 时写入；否则 NULL
);
CREATE INDEX IF NOT EXISTS idx_proposals_circle ON proposals(circle_id);

CREATE TABLE IF NOT EXISTS proposal_acks (
  proposal_id TEXT NOT NULL REFERENCES proposals(id),
  sub         TEXT NOT NULL,
  at          TEXT NOT NULL,
  PRIMARY KEY (proposal_id, sub)
);
CREATE INDEX IF NOT EXISTS idx_proposal_acks_proposal ON proposal_acks(proposal_id);
```

装配约定：

- `get()` 返回的 circle / proposal **形状与今天内存 dict 一致**（`members` 仍是嵌套数组，`acks` 仍是 `{sub, at}[]`），拆表只在 store 内部。
- `leave`：`DELETE` 该成员行（不是软删）。历史不靠成员表保留。
- `dissolve`：**UPDATE** `circles.status`，不级联删提案。
- `ingest_signal` 挂起的 `_signal_evidence`：**本单仍内存**（不是会务主路径；不挡 G6）。
- identity / session / contribution：**仍内存**（下一刀各自的单）。

建议新模块：`src/gfcc_kernel/circle_flow.py`（对标 `invites.py`），adapter 只调 store，不直接 `sqlite3.connect`。

## 5. 同事务（决策 ② 怎么落地）

现流程（`circle_web.api_ack`）：

1. `consensus.acknowledge` → 可能把状态打成 `consensus_verified`
2. 若 `can_complete` 且 `floor_sub == proposal.created_by` → `circle.advance_floor`

落库后：

- **未达成**（只追加一条 ack）：单步写 `proposal_acks` + 更新 `proposals.status`（自己的 `with connect()` 即可）。
- **刚达成**：`BEGIN` → 写 verified（`status`、`verified_at`、最后一条 ack）→ 写 `circles.floor_sub = next_floor(...)` → `COMMIT`。任一步失败则 `ROLLBACK`，HTTP 仍 400/现有错误，库里不得出现「已 verified 但地板还在提议人、且本该轮转」的半状态。

实现提示（任选，测试写死「同事务」）：

- `CircleFlowStore.transaction()` 产出同一 `conn`；`acknowledge` / `advance_floor` 增加可选 `conn=`；`api_ack` 在 verified 分支 `with transaction() as conn` 传入；或
- store 上一个 `verify_and_advance_floor(proposal_id, circle_id, proposer_sub)`，由 `api_ack` 在 `can_complete` 时调用。

禁止：两个 adapter 各 `commit` 一次还声称同事务。

提议人已 leave、地板已在 leave 时交接：**不要**再 `advance_floor`（现 §4.3 防双跳）。该分支只提交 ack/verified，不改 `floor_sub`。

## 6. 重启恢复

启动后（或每个 `get`/`list_all`）：

- 所有 `circles` + `circle_members` 能拼回今天的 circle dict（含 `floor_sub`）。
- 所有 `proposals` + `proposal_acks` 能拼回今天的 proposal dict。
- `PortRegistry` 仍构造 `CircleAdapter` / `ConsensusAdapter`；可在 `__init__` hydrate 缓存。
- 新进程里 `GET /circle/api/status` 不依赖旧 PID 的 dict。

单 worker 纪律不变（多 worker 会各写各的，G6 不解开）。WAL 可选，不强制；单 worker + adapter 锁 + 每操作用连接，与 invites 同级即可。

## 7. 测试隔离（仿 invites，必须写进本单）

`app._registry` 与 `get_store()` 都是进程单例。conftest 今天只把 `STORE_PROVIDER=stub`，**挡不住**本单默认写 `data/circle_flow.db`。

必须：

1. **每个测试**独立临时库：`CIRCLE_FLOW_DB` → `tmp_path`；`circle_flow._store = None`。
2. 重建（或替换）`app._registry` 里的 circle / consensus 适配器，避免 TestClient 打到上一用例的缓存。
3. 直接 `ConsensusAdapter()` / `CircleAdapter()` 的单测：hydrate 自当前 `get_store()`，因此 1 做完后才构造 fixture。
4. 新增用例文件建议 `tests/test_circle_flow.py`（或扩 `test_circle_web.py`），**monkeypatch 临时库**，不要碰开发者 `data/circle_flow.db`。

现有 pytest 必须全绿（圈测 + redeem + 轮询闸）。不要靠「单测继续纯内存、生产才写库」两条路径——生产和测试同一套 SQL。

## 8. 测试（最少覆盖）

落库：
