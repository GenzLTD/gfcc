## 0. 结论先行

薄壳**技术上能搭**。先接受一个体验折扣，不接受就停在本页、不要开工：

> **2026-08-29 验证坐实**：薄壳技术路径已真机跑通（§3.2 / §4.1 / §6），「技术上能搭」从推演变为实测；体验折扣与上架门禁仍在，§0 结论不受影响。

**元服务不支持 deeplinking / applinking / 隐式跳转。** 商店短链只能打开到元服务入口页，不能把完整 URL（含 `?i=` 兑换码）直接交给 Web 组件。

因此浏览器侧「点邀请链即入座」在元服务里**无法原样直达**，必须在 H5 二次承接（页内粘贴 / 扫码 / 落地页再跳到带 `?i=` 的会场）。这会削弱 D1 的核心体验。

若折扣不可接受：薄壳不值得做，鸿蒙用户继续用系统浏览器打开 `circle.genz.ltd`。  
若可接受（鸿蒙补充入口）：再按下文建 **Atomic Service 空工程**，不要用普通 App 模板改，不要复用 PlanetX `MyApplication`。

现况校准：`?i=` 是 16 位一次性**兑换码**，不是 JWT；仍是能力令牌。官方禁止把敏感信息放进 EnhancedWeb 的 **src 传参**——不要把 `?i=` 拼进 `src`。

## 3. AGC 域名白名单（两类都要配）

### 3.1 服务器域名（ArkTS `httpRequest` 等）

AGC → 元服务 → 基础服务 / 开发管理 → 域名配置。

| 类型 | 协议 | 建议值 |
|------|------|--------|
| httpRequest | `https://` | `https://circle.genz.ltd`（不配端口则 URL 不能带端口） |
| webSocket | `wss://` | 仅 H5 用 WS 时配 |
| download / upload | `https://` | 按需，v1 可不配 |

不能配 IP、localhost；单项 ≤ 128 字符；每类 ≤ 200 个；新增/更新约 **24 小时**生效；每月改次有上限（默认 50）。

### 3.2 业务域名（Web 加载 H5）

AGC → 元服务 → 域名配置 → 业务域名。

- 值：显式配 **`https://circle.genz.ltd`**，不要只配 `genz.ltd` 指望子域自动够用。  
- **组织门槛**：业务域名要求**已实名的非个人开发者**（企业/组织华为账号）。个人账号配不了 → 薄壳立项的第一道组织门。  
- 下载 `<APPID>.txt`（AGC 生成的数字文件名，如 `123456789.txt`，**不是**字面 `APPID.txt`）放到域名可访问根，例如 `https://circle.genz.ltd/<APPID>.txt`。天翼 `circle-genz` vhost 必须**单独 location 放行**（`location ~ ^/[A-Za-z0-9]+\.txt$` 挂 `/var/www/circle-genz-wellknown/`），不要被 `/circle/` 反代吞掉。iframe 域名一并配。仅**业务域名**需要放文件；**服务器域名**只配 AGC 白名单、不放文件。

**真机验证（2026-08-29，正式白名单）——悬念已闭环：**

| 01:30 | 校验文件未部署，天翼 404 | nginx error.log |
| 01:58 | `<APPID>.txt` 部署完成，curl 200（32B，内容 `cceb3a…`） | access.log |
| 02:04 | **AGC 官方校验机**（`139.159.167.164`，Apache-HttpClient/Java）抓取 `<APPID>.txt` 200 → **业务域名校验通过生效** | access.log |

## 4. AtomicServiceEnhancedWeb 最小骨架

`entry/src/main/ets/pages/CircleShell.ets`（启用时再入库；本预研只留形态）：

```typescript
import { AtomicServiceEnhancedWeb, AtomicServiceEnhancedWebController } from '@atomicservice/ascfapi';

@Entry
@Component
struct CircleShell {
  @State controller: AtomicServiceEnhancedWebController =
    new AtomicServiceEnhancedWebController();
  @State src: string = 'https://circle.genz.ltd/circle/';

  build() {
    Column() {
      AtomicServiceEnhancedWeb({
        src: this.src,
        controller: this.controller,
        onPageBegin: (event: OnPageBeginEvent) => {
          console.info(`[circle] onPageBegin url=${event.url}`);
        },
        onErrorReceive: (event: OnErrorReceiveEvent) => {
          console.error(`[circle] onErrorReceive ${event.error?.getErrorCode()} ${event.error?.getErrorInfo()}`);
        },
        onHttpErrorReceive: (event: OnHttpErrorReceiveEvent) => {
          console.error(`[circle] httpError ${event.response?.getResponseCode()}`);
        }
      })
    }
    .width('100%')
    .height('100%')
  }
}
```

`src` **固定**会场根，**不要**拼接 `?i=`。

`main_pages.json`：`"src": ["pages/CircleShell"]`。  
`EntryAbility`：`windowStage.loadContent('pages/CircleShell')`。

### 4.1 `?i=` 承接（须先拍板选一条）

| 方案 | 做法 | 利弊 |
|------|------|------|
| A 固定落地 + 页内承接 | 元服务永远加载 `/circle/`；H5 提供粘贴兑换码 / 扫码 | 最稳；体验折扣最大 |
| B 短链落地再跳 | 打开 `/landing`，H5 再 `location` 到 `/circle/?i=` | 依赖 Web 内跨路径跳转（2026-08-29 已真机实测，域名粒度间接闭环，见下） |

**方案 B 真机实测（2026-08-29，hilog 完整链路）**：按钮点击正常触发——注意进程 tag 是 `micservice.<APPID>` 而非 `CircleShell`，此前按 `grep CircleShell` 抓日志是**误判**。`loadUrl('https://circle.genz.ltd/landing')` 证据链（每次点击一致）：

`button clicked` → `[ASCF] CheckUrlAllow domainType:webView`（业务域名校验，**放行**）→ `onLoadIntercept /landing (result:0)`（未拦截）→ `onLoadIntercept /circle/ (isServerRedirect:1)`（服务器 302）→ `onPageBegin /circle/` → `onPageEnd 200 /circle/`（整页刷新回原页，视觉上「无动作」）。

**结论**：
1. **业务域名校验是域名粒度、不区分路径**——`CheckUrlAllow` 只校验 `circle.genz.ltd`，`/landing`、`/circle/`、`/circle/?i=test` 任一路径都不影响放行。**方案 B 的跨路径跳转（域名不变）由此间接闭环**，域名管控层面不再有悬念。
2. `loadUrl('/landing')` 实为「外部整页加载 + 服务器 302 兜底」，与「H5 内部 `location.href` 跳转」语义不同；且 `/landing` 并非服务器真实路径（vhost 无该条目，`location /` 兜底 302 到 `/circle/`）。原验证方式语义不成立，无需再测；H5 内部跳转若要用，选真实存在的路径（如 `/circle/?i=test`）。

不建议 src 传参带兑换码（官方禁敏感信息进 src）。

审核风险仍在：纯打开一个网站，可能被判「简单打包 / 最低功能」。薄壳若要过审，可能还要在 ArkTS 侧加非 Web 的最小会场能力——那已超出「薄壳」，另评估。
