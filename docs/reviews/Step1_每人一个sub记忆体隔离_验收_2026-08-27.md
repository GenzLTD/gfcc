## 一、改了什么（三处收紧全落地）

| 收紧项 | 改动 | 文件 |
|---|---|---|
| 1. Step 1 验 Dual 记忆体 | `recall` 必须带 `actor_sub`；`query`/`get` 无可见性直接抛错（防全表泄漏） | `slots.py`、`ports/memory.py`、`dispatcher.py` |
| 2. owner_sub 不可省略 | 无 circle_id 时必须 `actor_sub = policy.sub`；没有 sub → 401（不落 "system"）；`get(id)` 同一把尺子（B 猜 id → None） | `slots.py`、`app.py` |
| 3. HS256 密钥落地 | `.env` 配 `ETHOS_AUTH_SECRET`（≠ SIGNAL_INGEST_SECRET），重启进 HS256；签发脚本 4 张 JWT | `.env`、`scripts/issue_persona_tokens.py` |

具体：
- `StubStore` / `SQLiteStore`：`get(rid, *, actor_sub, circle_id)`、`query(filter_fn, limit, *, actor_sub, circle_id)` 两者都缺 → `ValueError`；新增管理面 `list_active()`（仅调试/运维）。
- `MemoryAdapter`：`recall(..., actor_sub, circle_id)`、`observe`/`supersede` 用带可见性的 `get`（非 owner → not found）；`list_all` 走 `list_active`。
- `dispatcher` memory 分支：`sub = ctx.policy.sub`，无 sub → `{"status":"error","error":"principal sub missing"}`（不再落 "system"）。
- `app._verify_request`：HS256 下 `verify` 失败（`ctx.error` 或 `principal=None`）→ 401（stub 模式无 token 仍放行，兼容本地联调）。
- `tests/conftest.py`：`ETHOS_AUTH_SECRET=""` 强制 stub（防 .env 填回污染单测）。

## 三、端到端验收（重启内核后实测）

```bash
# 密钥已入 .env（chmod 600），重启进 HS256
launchctl kickstart -k gui/$(id -u)/com.gfcc.kernel

# 签发（sub 对报名表，替换 --subs 实名单；token 只发本人）
cd ~/Projects/gfcc/services/gfcc_kernel
.venv/bin/python scripts/issue_persona_tokens.py --subs <报名表4人sub>

# 1) 无 token → 401
curl -s -X POST http://127.0.0.1:5211/v1/ask -H "Content-Type: application/json" \
  -d '{"message":"回忆专属机密","context":{"port_hint":"memory"}}'
# → {"detail":"unauthorized: missing token"}

# 2) A 记住
curl -s -X POST http://127.0.0.1:5211/v1/ask -H "Content-Type: application/json" \
  -H "Authorization: Bearer <A的token>" \
  -d '{"message":"记住专属机密：保险箱密码 2468","context":{"port_hint":"memory","session_id":"e2e-a"}}'
# → status ok + receipt id

# 3) B 问 → 0 条（Step 1 验收核心）
curl -s -X POST http://127.0.0.1:5211/v1/ask -H "Content-Type: application/json" \
  -H "Authorization: Bearer <B的token>" \
  -d '{"message":"回忆专属机密","context":{"port_hint":"memory","session_id":"e2e-b"}}'
# → "memory: no records yet (empty data is legal)"

# 4) A 自己问 → 命中 1 条
# → "memory: 1 record(s) found"

# 落库确认（actor_sub 即 sub）
sqlite3 data/memory.db "SELECT id, actor_sub, library FROM memory_records WHERE superseded_at IS NULL;"
```

## 四、运维注意

- `ETHOS_AUTH_SECRET` 与 `SIGNAL_INGEST_SECRET` 是两把不同的钥匙：前者管 /v1/ask 的人（HS256 JWT），后者管 /v1/signal-ingest 的信号链（HMAC）。勿混用。
- token 默认 30 天过期（`--days` 调整）；到期重签，sub 不变。
- 签发脚本默认 4 个占位 sub（tester-a/b/c/d）——**报名表定稿后，用 `--subs <真实sub>` 重签，token 只发本人，禁共用**。
- 单测 / CI 环境无 `.env`：conftest 显式 `ETHOS_AUTH_SECRET=""` 走 stub 验签，不影响生产 HS256。
