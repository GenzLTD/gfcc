### 密钥通道与 v0.4 误判（v0.5 修正）

**结论**：08-28 首场跑通是真 HS256，不是 stub 假通。密钥一直配着。配置通道**不是** systemd，而是 `app.py` 第 36 行模块级 `load_dotenv()`：

- systemd 没有 `EnvironmentFile` / `Environment=` **没关系**。
- `load_dotenv()` 从 `WorkingDirectory=/data/gfcc/services/gfcc_kernel` 读 `.env`，注入 `os.environ` 后 `build_security()` 才装配 → HS256 严格模式。
- redeem 签发端 `load_secret()` 读**同一** `.env` → 同源验签。

**v0.4 误判**（已作废）：只查 systemd 层就断言「环境变量空 → stub」，漏了应用层兜底。

**开场前定案（云机，一条命令）**：

```bash
journalctl -u gfcc-kernel --no-pager | grep -i ethos
```

| 日志 | 动作 |
|------|------|
| `ethos: HS256 strict mode enabled` | 严格模式正常 → **直接云机签发令牌、开闭门冒烟场** |
| `ethos: stub verify mode` | 才需要补密钥（概率低：`.env` 缺失或 `ETHOS_AUTH_SECRET=` 为空） |

可选（不挡开场）：unit 加 `EnvironmentFile=/data/gfcc/services/gfcc_kernel/.env`，把隐式 `load_dotenv()` 显式化。
