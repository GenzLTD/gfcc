### 2.1 拉取内核并重启（必须单 worker）

```bash
ssh <天翼机>          # 或直接在天翼终端
cd /data/gfcc
git pull              # 拉到 Gitee main，确认 git log -1 含本次变更
sudo systemctl restart gfcc-kernel.service
curl -s http://127.0.0.1:5211/health    # 确认 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:5211/circle/   # 确认 200
```

**写死单 worker**：圈/拍板/确认状态在进程内存。`uvicorn --workers 2` 时建圈和 ack
可能打到不同进程，表现为「入座了但没圈」。`gfcc-kernel.service` 的 ExecStart 必须单
worker（uvicorn 默认单 worker，检查 ExecStart 里没有 `--workers N` / `--reload`）。
**重启 = 本场作废**：内核一重启，圈内状态全清，testers 需重新建圈。场次开始后不要
重启内核，nginx reload 不影响内核进程。

### 2.2 nginx `/circle/` 反代 + `/circle` → `/circle/` 301（已插入）

已写在 `/etc/nginx/sites-available/looma`（`/tspace/` 与吞掉一切的 `location /` 之间）。备份 `looma.bak.circle`。下列配置仅供复原，不要再插第二份。

在 `server { listen 80 default_server; ... }` 块内应有：

```nginx
location = /circle { return 301 /circle/; }

location /circle/ {
    proxy_pass http://127.0.0.1:5211;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
}
```

注意顺序：`location /circle/` 与 `/v1/`、`/health` 并列即可（nginx 按最长前缀匹配，互不干扰；不要把 `/circle/` 写进 `/v1/` 的 location 内部）。

```bash
nginx -t && sudo systemctl reload nginx
curl -s -o /dev/null -w "%{http_code}\n" http://14.29.216.219/circle/   # 期望 200
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://14.29.216.219/circle   # 期望 301 → /circle/
```


把每人的 token 私发对应 tester（微信单聊，勿发群里），并同时发带圈号的深链：
`http://14.29.216.219/circle/?c=<圈号>`（B/C 打开即带圈号，微信里传 36 位 UUID 掉字率高）。
testers 操作流程（页面引导，对应 testers 须知）：
1. 粘贴令牌 → 入场（页面提示「令牌是你本人的钥匙，不要转发」）
2. A 写真议题名建圈 → 生成深链发群；B 打开深链点「入座 · 参与确认」；C 打开深链点「只旁观 · 先只看」（**C 不入座**，不入 parties，不需要确认）
3. A 写拍板句（subject + 一句依据）→ 提交（仅 A 有该按钮）
4. A、B 各自用自己的令牌点「我本人点确认」
5. 全员确认后状态变「已达成共识」（页面显示 已确认 x/y）
6. 页面底部明示：本场只验「本人点确认」；引用上一条与认定/兑现，下一场再做

签发在哪台机器，就读哪台的 `.env`。云上场次不要用本机 token 冒烟。

## 5. 边界与已知项

- **明文传输**：天翼 80 是 HTTP 无 TLS，令牌经公网明文传输。可接受（测评一次性、令牌短期有效）；若需加固再配 443。
- **令牌存储**：页面用 `sessionStorage`（关标签即清），不用 `localStorage`；场次结束点「退出」先调 `/circle/api/leave` 再清本地。深链只带 `?c=`，**不带 token**。
- **单 worker 强约束**：进程内状态，`--workers N` 会让建圈/ack 打到不同进程（表现为「入座了但没圈」）；重启 = 本场作废。场次中勿重启内核（nginx reload 不影响）。
- **status 需 Bearer**：C 也要自己的令牌才能看状态（不公开扫圈号），但不必入座、不进 parties。`api_status` **原样返回** circle（含 members），不做角色过滤；存档时 members 为空 = 人已 leave，身份以 `created_by` + 拍板句 `parties` 为准。
- **sub 隔离**：A 记住、B 问不到由 Step 1（memory port 按 sub 隔离）保证，与围坐页无关。Step 2（会话落盘）/ Step 3（知识库 `kb:{sub}`）/ Step 4（围坐引用）未做。
- **旁观 C**：不在拍板句 parties 内时 ack 会被拒（"not a party"）。换人当组织者 = **另建一圈**，不是「C 凭痕迹升级」。
- **下一场要对齐的产品链**（会场页尚无入口）：memory `refs` 指向共识 id；contribution 他认 attest → steward fulfill → identity `capability_trace`；C 升级引用 Dual/CoCo。细节见纪要 §四与清单 §5，不在本手册展开。
