### 3.1 方案 D：大陆产品全部迁到天翼云同机（运维简化，不是自动闭环）

把 **Looma 后端、PlanetX、T-space、Bolent** 与已在天翼云的 GFCC docker / 内核放在同一台 `14.29.216.219`，对齐 08-25 已拍板的「一台高性能机」：内环 `127.0.0.1`，外环 Nginx 按 Host 出站。

**会极大简化的（网络与适配）：**

| 项 | 同机之后 |
|----|----------|
| ingest URL | `http://host.docker.internal:5211/v1/signal-ingest`（现网 §8.1：Looma 走 Docker；宿主机进程跑法才用 `127.0.0.1:5211`，与 G3 / ServBay 联调同形） |

- **L3 出站代码**：必须把 THOMAS 的 `send_gfcc_personality_beacon` 合进正在部署的那份 Looma。同机只是 URL 变成回环，没有这段代码仍是 skip。

### 3.3 本阶段只做中央机（已拍板）

**先中央机接入，三台终端机后置。** 可以这样实施，而且应该这样切：终端反代要等中央机环 1 先绿，否则三台入口仍指向旧大脑，查日志会对不上。

本阶段范围（做）：

1. 天翼云成为唯一大陆产品机：Looma `:5200`、PlanetX `/`、T-space `/tspace/`、Bolent（若本阶段来不及，门户可仍留阿里云，**不挡环 1**）。  
2. `gfcc_kernel` systemd 常驻 `5211`（**绑 `0.0.0.0`**——Docker `host.docker.internal` 打不到只绑回环的口，见 §8.1；**安全组不放行**，等价回环由安全组闭合 + HMAC）。  
3. 把 THOMAS 出站合进部署到天翼的那份 Looma；`GFCC_SIGNAL_INGEST_URL=http://host.docker.internal:5211/v1/signal-ingest`（Looma 走 Docker，以 §8.1 现网为准）；内测 `SIGNAL_INGEST_SECRET`。  
4. 人从 **天翼云 IP/Host** 打开 PlanetX 完成测评，对账 `signal_log`。  
5. 腾讯云 / 阿里云 / Vultr **先不动角色**；只确认它们 **没有** 配置格契 ingest（海外 `api.genz.ltd` 的 URL 保持空）。

### 3.4 中央机端口协调（对照天翼现网清单，2026-08-26）

天翼现网三层划分 **冻结**：格契侧不改号、不把内部口映射到宿主、不把五槽当成 TCP。入驻的 THOMAS 产品栈 **另开一层**，只加 Nginx 人网口；信号 **不新开端口**。

#### 已占用（入驻服务禁止改、禁止复用）

| 层 | 端口 | 谁用 | 入驻服务怎么对待 |
|----|------|------|------------------|
| 公网安全组 | 22 / 5210 / 5220 / 3210 | SSH、Tatha、DemoPeter、am-gateway | **原样保留**。Looma 不要监听 5210，Nginx `/v1` **不要**反代到 5210 |
| compose 内 | 3111 / 3112 / 49134 / 3220 / chroma:8000 | 记忆引擎与 DemoPeter 向量库 | 不映射宿主。Looma **不要**加入 `gfcc` compose 网络去打这些口 |
| 宿主机进程 | **`0.0.0.0:5211`**（§8.1 现网） | `gfcc_kernel` | **唯一**链 B 收信 TCP。绑 `0.0.0.0` 是为容器 `host.docker.internal` 可达；等价回环靠**安全组不放行** + HMAC 闭合。误开安全组 = 面暴露（记账见 §8.4） |
| 逻辑槽 | circle / identity / memory / consensus / contribution | 信封路由，非 TCP | Looma 只 POST 信封；由内核按 `signal_type` 进槽，发送端不配「槽端口」 |

#### 入驻要新开的（产品栈，与格契并列）

| 端口 | 绑定 | 服务 | 安全组 |
|------|------|------|--------|
| **80**（本阶段；443 后续） | `0.0.0.0` | **Nginx**：`/` PlanetX、`/tspace/` T-space、`/v1`+`/health` → Looma | **必须新放行**（现清单没有 80，人不进不了站） |
| **5200** | **127.0.0.1** | Looma gunicorn | **不放行**。禁止照搬腾讯云 `0.0.0.0:5200` |
| Looma Chroma | 只进 `looma-net`，容器内仍 8000 | 诗词/产品向量，**另一份** Chroma | **不映射** `0.0.0.0:8000`（腾讯云现网脏面勿复制）。与 gfcc `chroma:8000` 分属两个 compose，容器口可同号 |
| Redis 6379 | 只进 `looma-net` 或不映射 | 限流/缓存 | **不放行** |
| 静态站 | 无独立 TCP | PlanetX / T-space 构建产物由 Nginx 直接出 | — |
| Bolent | 本阶段可仍留阿里云 | 不挡环 1 | 若同机再议 Host，不要占 5210 |

`5210` 与 `5200` 都叫 `/v1/ask` 形态，但是 **两套 API**：Tatha 是格契中央大脑；Looma 是职业产品。Nginx 按 path 切开即可，不要合并进程。

#### 内部通讯矩阵（谁打谁）

```
人网     浏览器 ──TCP 80──► Nginx
                              ├─ /  /tspace/     静态
                              └─ /v1 /health ──► 127.0.0.1:5200  Looma

链 B     Looma ──HTTP──► host.docker.internal:5211/v1/signal-ingest
         （HMAC X-Signature；SIGNAL_INGEST_SECRET）
         内核收信封后路由 identity 等五槽（无新 TCP）

链 A     DemoPPI（环 2）──► 5211/v1/signal-ingest **直打**（G3 真路径，§5 施工单）
         环 2 信号段按此对账；「经 Looma 中转再 fan-out」是另一条线，本方案不混验

格契内环  tatha:5210 ──compose DNS──► demopeter:5220
                              └──► am-gateway:3210 ──► am-bridge:3220 ──► am-engine
         入驻产品栈不加入这条链
```

**禁止的连线（同机 ≠ 同系统）：**

- Looma ↛ Tatha `:5210`、↛ DemoPeter `:5220`、↛ am-gateway `:3210`、↛ 格契 SQLite  
- PlanetX 浏览器 ↛ 直打 `:5211` 或 `:5200`（只打 Nginx `:80` 同源 `/v1`）  
- 入驻 Chroma ↛ `CHROMA_HOST=chroma`（那是 gfcc compose 服务名）

#### Docker 回环陷阱（Looma 若走容器）

宿主机内核绑定 **`0.0.0.0`**（§8.1 现网）时，容器内用 `host.docker.internal` 可达；若内核只绑 `127.0.0.1`，**容器内的 `127.0.0.1` 是容器自己**，打不到内核。

| Looma 跑法 | `GFCC_SIGNAL_INGEST_URL` |
|------------|--------------------------|
| 宿主机进程（systemd gunicorn） | `http://127.0.0.1:5211/v1/signal-ingest` |
| **Docker（现网已定，§8.1）** | `http://host.docker.internal:5211/v1/signal-ingest`，compose 加 `extra_hosts: ["host.docker.internal:host-gateway"]` |
| 不要用 | `http://14.29.216.219:5211/...`（会逼你给 5211 开安全组） |

`ports: "5200:5200"` 请改成 `"127.0.0.1:5200:5200"`，只给本机 Nginx 反代。

#### 环境变量（天翼这一份 Looma）

```bash
FLASK_PORT=5200
# 现网（§8.1）：Looma 走 Docker
GFCC_SIGNAL_INGEST_URL=http://host.docker.internal:5211/v1/signal-ingest
# 仅当改回宿主机进程跑法：http://127.0.0.1:5211/v1/signal-ingest
SIGNAL_INGEST_SECRET=<内测新值，与内核同一把，≠ ETHOS_AUTH_SECRET>
```

内核侧（§8.1 现网）：`--host 0.0.0.0 --port 5211`；`SIGNAL_INGEST_SECRET` 同上。**不**给 Looma 配「identity 端口」之类变量。安全组**禁止**放行 5211。

#### 安全组增量（仅中央机本阶段）

| 动作 | 端口 |
|------|------|
| 保持 | 22、5210、5220、3210 |
| **新增** | **80**（人测 PlanetX；443 有证后再加） |
| 明确不开放 | 5200、5211、8000、6379、3111、3220 |

### 10.3 验证器 ≠ 判据已得分

五条判据（记得住 / 协商得了 / 贡献兑得现 / 人往高处走 / AI 不抢戏）的对象是**围坐结果**。现网立住的是**验证器**：

- 冻结信封 + 确定性路由（`signal_type` → 端口）
- 无 `score_evidence` 出不了 `proposed`（单测硬约束；现网未走完 propose → score → ack）
- 禁 AI ack（静态约束）
- 环 1 验到 `personality_beacon` 进 identity 端口 + auxiliary trace
- 环 2 验到 `consensus_match` 进 consensus 端口（`signal_log` 3 行，§8.5）；**没验过 memory 引用**，也没走完 propose → score → ack

措辞纪律：写「验证器在」，不写「判据已半落地」。
